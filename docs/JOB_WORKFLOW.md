# MAC単位の作業管理（2.0）

既存のUSB外観検査、option=3 Reset、RTSP/IR-CUT判定、config導入、貼紙確認後の目標IP変更を利用します。

## 作業を開始

主画面で1台 / 1×2 / 2×2 / 2×3を選択します。Carton番号、箱の最大OK台数、Base IP（作業用）を入力します。Base IPはPCの実際のネットワーク内に指定します。PCのネットワーク設定は自動変更しません。

Base IPから台数分の連続IPを用意します。使用中IPは上書きせず、割り当て済みMACだけ直接HTTPで確認します。ネットワーク全体のIPスキャンは行いません。L2情報取得は新しいMACの検出と復旧に使用します。

最終IPは従来どおり主画面の開始IPと設定の目標範囲を使用し、貼紙完了を確認してから変更します。作業用Base IPとは別です。

## 保存場所

- `data/current_job.json`: MACをキーとする作業状態、Carton、モード、IP、各検査結果。tmp、flush、fsync、replaceで保存。
- `data/result.csv`: 最終結果の正式履歴。record_idで重複追加を防止。
- `data/pending_post.json`: 将来のPOST用送信待ちデータ。現時点では送信先未設定のため自動送信しません。
- `data/history/`: 新しい作業を選んだ場合の前作業、および終了作業のバックアップ。
- `data/logs/tool.log`: 実行ログ。ローテーションあり。
- `records/network_workflow.json`: MACの作業IP占有、目標IP予約、L2機器情報。起動後も占有MACへのSET再送を禁止。

既存の検査CSVと証跡保存も維持します。外観NGは途中の検査結果として保持し、最終結果と区別します。

## 再開とエラー

起動時に前回作業の通知を表示します。「確認して続ける」は通知を閉じるだけ、「計数器をクリア」はOK/NG表示のみをクリアします。どちらも相機処理・履歴削除・MAC保護解除を実行しません。主画面で検査開始を押した時に保存済み作業を再開します。再開では同じMACの記録を使い、IP変更済みの作業IPを再確認します。config適用済みの場合は再アップロードせず貼紙確認へ進みます。最終IP変更中だった場合は目標IPとMACの一致を確認するまで再送しません。

Windowsによる一時的なJSONアクセス拒否には待機して再試行します。保存できない状態が続く場合はメモリに更新を保持し「保存待ち」とログで通知、バックグラウンドで再試行します。この表示中の強制終了では未保存更新が失われる可能性があります。以前の正常JSONを直接上書きしません。

ERRORの相機は「再確認」でHTTP確認から再試行できます。作業IPのSETを繰り返しません。接続状態が不明のときはMAC占有を保持します。断電確認後に占有を解除します。

同じ正式作業の再確認で結果が変わった場合は同じrecord_idのCSV行を原子的に訂正し、重複行を追加しません。以前のエラーは実行ログと作業状態のerror項目に残ります。

IR-CUTは `samples/ir_cut_sample.py` の判定アルゴリズムを使用します。操作員に「蓋を被ってください。」を表示し、「蓋を被せた · 開始」で検査開始。0.5秒間隔・連続3回で黒白を確認したら「蓋を外してください。」を表示し、連続3回でカラー復帰を確認すると自動OK、config書込へ進みます。RGB差4.0未満かつ彩度8.0未満を黒白とします。各段階90秒でタイムアウトし、手動NGまたは再試行を選べます。NG画像確認中は自動判定を止めます。

外観NGは「外観不具合」と「破損」に分類します。どちらもB系統の証拠画像を保存し、理由を記録、以後の検査へ進みます。

Cartonの台数にはOKだけを数えます。上限到達後は次のCarton番号を作業員が入力します。番号を自動変更しません。

## GAS / HTTP POST

設定の「6 GAS送信」で `/exec` URLを保存します。自動送信を有効にすると完了履歴を送信し、失敗分は60秒間隔で再試行します。「接続テスト」はtype:testのダミーデータのみ、「未送信履歴を再送」は保存済みPENDING履歴を送信します。examples/gas_receiver.gsを設定画面から表示・保存できます。Script Property SPREADSHEET_IDに保存先スプレッドシートIDを設定してデプロイします。

送信はJSONです。GASのリダイレクトを追い、返信JSONの `ok === true` と同じ `record_id` で受領を確認します。HTTP 200単独では成功にしません。応答本文とHTTPステータス（診断用）を画面とpending_post.jsonのlast_responseに保存します。失敗は本地の検査結果を変更しません。

受信例はrecord_idで行を重複させず、訂正結果があれば同じ行を更新します。type:testはスプレッドシートに追加しません。未送信履歴の再送には以前の完了記録も含まれます。

## POSTアダプタ

`JobStore.deliver(sender)` が送信アダプタの入口です。例外時はPENDING、retry_count、last_error、last_retryを保存します。外部通信中は作業状態のロックを保持しません。実際のUG65/GAS接続先、認証と送信形式は今後設定する必要があります。

検証はオフラインの模擬機器による回帰とブラウザの表示確認です。六台実機、強制終了後の実機復旧、実際のPOST接続は別途現場検証が必要です。
